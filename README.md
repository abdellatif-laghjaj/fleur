A native Kotlin/Jetpack Compose budget app rebuilt from the supplied Fleur screenshots and the recovered Android APK references. The project uses the original paper textures, heading fonts, category vectors, and tab icons. Its application ID is `com.abdellatif.fleur`.

There are no subscriptions, purchase screens, ads, analytics SDKs, server accounts, or feature locks. New installations start with an empty budget and a Cash account. The populated screenshots are generated by tests in a separate database; sample transactions are never inserted into your budget.

## Build and run

Open this folder in Android Studio, or run in PowerShell:

```powershell
.\gradlew.bat :app:assembleRelease
```

The personal-use APK is `dist/Fleur-Personal-1.0.apk`; Gradle produces it at `app/build/outputs/apk/release/app-release.apk`. A debug build is also available with `:app:assembleDebug`. The project uses the existing Gradle 9.6 / Android Gradle Plugin 9.5 configuration, JDK 25, and Android SDK 37. `local.properties` points to the SDK on this workstation; other machines should configure their own SDK path.

To install on a chosen device:

```powershell
$adb = Join-Path $env:LOCALAPPDATA 'Android\Sdk\platform-tools\adb.exe'
& $adb devices -l
& $adb -s emulator-5554 install -r .\app\build\outputs\apk\release\app-release.apk
& $adb -s emulator-5554 shell am start -n com.abdellatif.fleur/.MainActivity
```

Both variants use this workstation's Android debug key. The release variant shrinks resources and optimizes the whole app with R8; it is an installable personal build, not a Play Store publication. Keep the signing key if you want to install future updates over existing data.

## Included

| Area | Behavior |
| --- | --- |
| Home | Income, expenses, period balance, carryover, category budgets, total budget and striped progress bars |
| Insights | Striped donut, category totals/percentages, category drilldown, daily spending and averages |
| Transactions | Income, expenses, transfers, notes, paid status, future dates, search, account/category/type/paid filters, and calendar |
| Repeating entries | Daily, weekly, fortnightly, monthly, quarterly, yearly, custom intervals/weekdays, month-end and end dates; one-occurrence or following-series edits/deletes |
| Accounts | Spending, savings and debt accounts, opening balances, goals, debt limits, balance updates, transfers, hide/unhide, reorder and confirmed deletion |
| Categories | Custom income/expense categories, 697 original icons, 30 colors, category search, budgets, reorder and safe deletion |
| Appearance | Paper background, light/dark/system mode, accent colors, eight heading font choices, heading size and optional decimal display |
| Preferences | Currency, default account/paid status, budget frequency, month start, week start, carryover, haptics and visibility controls |
| Android features | Document-picker backup/restore and CSV/PDF export, daily reminders, device-credential app lock, and home-screen summary widget |

Long-press and drag accounts or categories to reorder them. Arrow controls are also available for category order, and account details include Move up / Move down.

Account balances include paid transactions through today. The period summary and budgets include transactions scheduled in the selected period, so future entries can appear there before changing today's account balance. Transfers do not count as income or expenses. Transfers involving debt affect the account balances; debt-account income/expenses are separated from the main summary.

All amounts use integer hundredths and exact decimal parsing. Recurring month-end dates do not drift after February. A single edited occurrence retains its own date and paid state independently of its series.

## Data and exports

- SQLite stores accounts, categories, transactions, repeat exceptions, budgets, and settings locally. Saves use transactions and only write changed records.
- A JSON backup preserves the entire budget, including recurrence and paid-state exceptions. Restore validates the complete backup before replacing data and retains a recovery copy of the previous budget in the app's private `before-restore.json` file.
- CSV and PDF exports use the date range selected in the app. CSV preserves full notes and quotes multiline values. PDF reports wrap long notes and continue onto additional pages. Text that could execute as a spreadsheet formula is escaped.
- Hiding an account preserves its history. Deleting an account requires confirmation and removes its transactions and transfers. Used categories cannot be deleted while transactions still reference them.
- App Lock uses the phone's existing PIN, password, or pattern and hides widget amounts while enabled. Configure a device screen lock before enabling it. Leaving the app relocks it, including visits to the Android file picker.
- Reminders use Android's battery-friendly alarm scheduling, so the system may deliver them after the selected minute.

The backup format is this app's `fleur-personal` JSON format. It does not claim compatibility with the original developer's `.fleur` files. Apple iCloud synchronization and sharing are not available on Android; this app does not connect to the original developer's services.

## Verification

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug
$env:ANDROID_SERIAL = 'emulator-5554'
.\gradlew.bat :app:connectedDebugAndroidTest
```

JVM tests cover exact money, recurrence scheduling and exceptions, leap/month-end behavior, carryover periods, debt transfers and reorder integrity. Instrumentation tests use separate temporary databases and cover durable storage, backup validation, exports and actual Compose editing flows. Screenshot artifacts are copied into `qa/screenshots/`.

See [QA evidence](qa/VERIFICATION.md) for test results, runtime checks, screenshots and remaining limits. See [implementation requirements](docs/IMPLEMENTATION.md) for the reference inventory and acceptance checklist. Build/test reports are generated under `app/build/reports/`, and command logs are under `qa/`.

## Source layout

- `data/Models.kt` and `BudgetActions.kt`: financial and recurrence rules.
- `data/BudgetDatabase.kt` and `StateCodec.kt`: SQLite and backup validation.
- `data/BudgetViewModel.kt`: asynchronous persistence and UI state.
- `ui/`: Compose screens, editors, theme, charts and icons.
- `platform/`: Android reminders and the summary widget.
- `MainActivity.kt`: document pickers, app lock and platform integration.

Reference decompilation and source APKs remain in the parent directory. This project is a Kotlin rebuild; obfuscated decompiled Java is not part of its build.
